# 科创部门适配测评动态纪实改版设计规格

日期：2026-08-08

## 1. 项目目标

在保留现有测评逻辑、七部门匹配结果、匿名本地存储和移动端可用性的基础上，重点解决三个问题：

1. 答题页只有题目和选项，缺少过程感与视觉反馈。
2. 结果页信息完整但视觉节奏平，缺少具有记忆点的揭晓时刻。
3. 部门详情页内容浅，真实工作、成果和成长价值展示不足。

改版后的体验应让新生感到这是一次“从个人协作信号进入真实科创现场”的探索，而不是一套普通在线问卷。

## 2. 已确认的设计方向

### 2.1 视觉论点

一次从个人协作信号出发，进入真实科创工作现场的探索。

### 2.2 主导视觉系统

真实活动照片、成果数据和工作流程占视觉与内容主体；扫描界面、光路、动态排版和轻量空间感负责科技包装。整体比例约为 65% 真实纪实、35% 科技沉浸。

### 2.3 标志性时刻

完成第 20 题后，20 次选择形成光路并聚合为个人画像，首选部门从雷达坐标中锁定，真实部门照片随结果一起展开。

### 2.4 页面节奏

- 欢迎页：建立科创扫描入口，保留现有雷达识别度。
- 答题页：稳定、专注、逐步积累，不提前暴露部门排名。
- 结果揭晓：短时间集中释放动效，形成全站视觉高潮。
- 部门详情：从科技界面过渡到真实工作纪实，鼓励继续探索。

### 2.5 色彩逻辑

- 深黑与中性灰：界面底色和科技氛围。
- 青蓝：扫描、进度和普通交互状态。
- 暖金：匹配结果、关键数字和主行动。
- 部门识别色：仅用于详情页局部强调，从部门照片或现有汇报视觉中提取。

### 2.6 克制规则

- 不堆叠玻璃卡片。
- 不使用满屏持续粒子、渐变光球或无意义装饰。
- 不让所有文字和控件同时发光。
- 每页只保留一个主动态焦点。
- 光效不得遮挡真实照片、人脸、正文或操作控件。

## 3. 页面设计

### 3.1 欢迎页

保留现有雷达入口及品牌识别，但增强左侧空间层次和雷达坐标密度。雷达继续作为测评入口，不将整站限制为纯雷达主题。首屏保留下一段内容提示，避免页面看起来像单张海报。

### 3.2 答题页

#### 页面结构

- 顶部：中心名称、当前阶段、返回控制。
- 桌面左侧：信号采集仪、阶段编号、四条动态轨道。
- 桌面右侧：题目情境、四个选项、上一步与下一步。
- 手机端：信号采集仪压缩为顶部横向轨道，题目保持单列。

#### 交互与动效

- 选项悬停时出现边缘追光，选中后轻微下压并回弹。
- 选中答案后，一条短促光流从选项汇入进度轨道。
- 每 5 题进入一个阶段：观察、协作、执行、表达。
- 阶段切换时更新背景网格、照片切片和简短状态提示。
- 只显示“协作画像正在形成”，不显示实时部门排名或维度分数。

#### 光效强度

答题页使用全站最克制的光效。背景扫描光带缓慢移动，交互光流只在作答后短暂出现。

### 3.3 结果页

#### 揭晓序列

1. 提交后进入约 1.2 至 1.8 秒的信号聚合。
2. 四维数据形成光路并汇入雷达坐标。
3. 首选部门被锁定，匹配度数字计数到最终值。
4. 首选部门真实照片展开，进入结果首屏。

揭晓过程不得用普通加载转圈，也不得让用户等待超过约 2 秒。

#### 页面结构

- 首屏：部门真实照片、部门名称、匹配度、自然语言适配结论。
- 个人画像：八点雷达轮廓展示四个主维度及细分表现。
- 适配依据：把用户倾向与首选部门真实任务逐项对应。
- 备选对比：横向比较两个备选部门的适合点和实际区别。
- 个人结果海报：本地生成，可保存，不上传答案或个人信息。
- 行动区：查看首选部门、探索全部部门、重新测评、加入咨询群。

#### 光效强度

结果页是全站动效最强的页面，但高强度动效集中在揭晓阶段。进入阅读状态后，背景只保留低频光带和局部扫光。

### 3.4 部门详情页

七部门共用同一页面骨架，照片、工作流程、成果、成长价值和部门识别色不同。

#### 页面结构

1. 现场首屏：高质量真实照片、部门名称、核心职责、成果数字。
2. 你会参与什么：展示一次真实任务的完整流程。
3. 工作现场：2 至 4 张照片错位编排并配简短说明。
4. 真实成果：使用 PPT 中可核实的数据，通过计数和时间线呈现。
5. 你能获得什么：具体技能、经验和成长场景。
6. 适合这样的人：结合测评维度解释适配，不将部门限定为单一性格。
7. 继续探索：两个相近部门、全部部门入口、咨询群入口。

#### 动效

- 首屏照片使用光幕揭示，不使用模糊占位作为最终视觉。
- 图片滚动进入时使用轻微视差和景深变化。
- 成果数字进入视口后计数一次，不循环播放。
- 部门切换保持共享元素连续性，让部门名称或主图自然过渡。

## 4. 七部门内容与素材计划

### 办公室

- 主图：培训课堂或大型活动合影。
- 过程图：双选会、物资与活动统筹。
- 重点内容：33 项报销材料审核、3 期财务实操培训、十余场活动统筹、跨部门协调。

### 项目部

- 主图：科技立项会议。
- 过程图：月度交流会、项目跟进、交流合影。
- 工作证据小图：项目周表、问题清单、群聊或表格截图。
- 重点内容：50 项结题、10 项优秀项目、4 项进入省赛、2 项进入省赛决赛、后续 4 期选题咨询会与 20+ 项目培育计划。

### 竞赛部

- 主图：路演或培训现场。
- 过程图：材料评审、专家培训、赛事支持。
- 重点内容：材料收集、赛道分类、专家送审、真实性审查、反馈整改和现场支持。

### 科素部

- 主图：答辩或培训现场。
- 过程图：文献综述、科技制图、科技论文比赛与技能培训。
- 工作证据小图：社群宣传和课程截图。
- 重点内容：学术写作、PPT、路演答辩、AI 工具和项目孵化闭环。

### 赛训部

- 主图：获奖团队或科技文化节现场。
- 过程图：实物展示、选题咨询会、带队保障。
- 重点内容：3 个省级特等奖、1 个一等奖、7 个二等奖、8 个三等奖及赛事“优胜杯”。

### 宣传部

- 主图：跨校交流或活动纪实。
- 过程图：栏目封面、展板、会议、团队合影。
- 重点内容：科创 idol、赛事情报站、赛事交流营、校内外宣传和科创 IP 建设。

### 语培部

- 主图：路演训练。
- 过程图：表达打磨、人文活动、手工制作。
- 重点内容：逻辑表达、限时答辩、仪态训练、模拟演练与校内外导师联动。

### 通用素材规则

- 每个部门使用 3 至 5 张有效图片。
- 主图必须清晰、有真实人物或活动主体，不使用群聊、表格和模糊截图。
- 聊天截图、表格和宣传图只作为小尺寸证据，不承担主视觉。
- 图片统一转换为 WebP，并提供桌面与手机尺寸。
- 现有真实素材足够，暂不使用 AI 生成人物图片。

## 5. 动效与光感系统

### 5.1 层级

- 主动效：页面揭晓、阶段切换、部门切换。
- 状态动效：答案采集、数字计数、进度点亮。
- 环境动效：低频扫描光带、局部边缘光、轻微照片视差。

### 5.2 强度分配

- 结果页：最强。
- 部门详情页：中等。
- 答题页：最克制。

### 5.3 时间规则

- 普通反馈：150 至 300 毫秒。
- 页面内容进入：350 至 650 毫秒。
- 结果揭晓：总时长约 1.2 至 1.8 秒。
- 持续环境动效必须低频、低对比，并在页面失焦时暂停或降低频率。

### 5.4 无障碍降级

检测 `prefers-reduced-motion`。减少动态效果时取消视差、粒子、磁吸和长距离移动，保留不依赖运动的颜色、层级和状态反馈。

## 6. 技术结构

### 6.1 保留内容

- React、Vite、TypeScript 技术栈。
- 现有 20 题、计分逻辑、四维画像和七部门匹配。
- 会话恢复、匿名本地存储和结果返回逻辑。
- 现有测试基线。

### 6.2 内容模型扩展

在 `Department` 中增加以下结构化字段：

- 视觉主题与部门识别色。
- 首图与相册素材。
- 核心职责。
- 成果数据。
- 工作流程。
- 成长收获。
- 适合人群与测评维度映射。
- 相近部门推荐。

内容保持静态本地数据，不新增服务器或数据库。

### 6.3 组件边界

- `SignalProgress`：答题阶段和信号采集反馈。
- `AnswerOption`：选项交互、选择状态和光流触发。
- `ResultReveal`：结果聚合与部门锁定序列。
- `ProfileRadar`：八点个人画像与可访问文字摘要。
- `DepartmentHero`：部门主图、使命和成果摘要。
- `WorkflowTimeline`：真实任务流程。
- `EvidenceGallery`：照片与工作证据。
- `ResultPoster`：本地结果海报生成与下载。

组件只负责一种明确职责，部门文案和素材不硬编码进展示组件。

### 6.4 动效实现

- 使用项目现有 `motion` 处理 React 状态转场和共享元素过渡。
- `OGL` 只用于欢迎页或结果揭晓中的轻量光场，不扩展为每页独立 WebGL 场景。
- CSS 负责按钮追光、扫描线、局部高光和静态降级。
- 不引入多个功能重叠的动效库。

### 6.5 图片处理

- 从 `design-research/ppt-media` 中筛选原始素材。
- 使用 `sharp` 生成 WebP 和响应式尺寸。
- 为首图规定稳定宽高比和焦点位置，避免加载后布局跳动。
- 非首屏图片启用懒加载。

## 7. Figma 与 HyperFrames 分工

### Figma

- 建立答题、结果和部门详情三个关键页面的桌面与手机关键帧。
- 校准网格、间距、文字层级、图片裁切和部门识别色。
- 在可用时制作结果揭晓的静态关键状态或短时间线，用于实现前对照。
- Figma 设计只作为视觉基线，不成为运行时依赖。

### HyperFrames

- 用于梳理结果揭晓的时间线、光路聚合、照片揭示和文字进入顺序。
- 参考其“先确定最终版式、再添加动画”的方法，避免动画结束位置靠猜测。
- 必要时制作低分辨率动效样片，用于检查节奏，不将 HyperFrames 代码直接嵌入网页。
- 复用其动画地图、转场和对比度检查思路，校准网页中的 Motion 实现。

### 可用性说明

两个插件已安装，但是否能直接调用取决于当前任务是否挂载对应接口。插件不可调用时，网页实现不被阻塞，仍按已确认的关键帧、时间线和测试标准完成。

## 8. 错误处理与降级

- 主图加载失败：显示部门识别色、部门名称和文字摘要，不留下空白区域。
- 动效模块失败：直接显示最终内容，不阻塞答题或查看结果。
- WebGL 不可用：切换为 CSS 扫描线和静态背景。
- 结果海报生成失败：保留浏览器截图友好的静态结果卡，并给出重试操作。
- 会话数据不完整：沿用现有返回首页和重新测评逻辑。

## 9. 验证标准

### 功能

- 20 题完整作答、前后切换和提交正常。
- 首选与备选部门结果不受视觉改版影响。
- 会话恢复、重新测评、部门返回和咨询群入口正常。
- 结果海报可在本地生成并保存。

### 视觉

- 检查 375、390、768、1024、1440 像素宽度。
- 答题控件、雷达、成果数字和图片容器尺寸稳定，无布局跳动。
- 文字不溢出、不遮挡照片主体、不与按钮重叠。
- 七部门主图裁切合理，手机端仍能看清主要人物或活动。
- 光效不压低正文对比度，不形成大面积同色发光。

### 动效与性能

- 普通交互响应及时，不因动效延迟答题。
- 手机端降低粒子、滤镜和视差强度。
- `prefers-reduced-motion` 下核心流程完整且无长距离运动。
- 页面失焦后持续动画暂停或降频。

### 自动化验证

- 运行现有 Vitest 单元测试并补充新增组件测试。
- 运行 Playwright 完整答题、结果、详情和返回流程。
- 增加桌面、手机和 reduced-motion 截图检查。
- 检查控制台错误、图片 404、横向滚动和关键元素不可见问题。

## 10. 不在本轮范围

- 正式上线部署和域名配置，需在改版验收后再次确认。
- 后台管理系统、账号体系和云端答题数据统计。
- 七部门独立设计为七套完全不同的网站主题。
- 自动播放带声音的视频、复杂 3D 场景和高负载全屏粒子系统。

## 11. 完成定义

当以下条件同时满足时，本轮改版完成：

1. 三类核心页面达到已确认的动态纪实方向。
2. 七部门均有真实、具体、可探索的详情内容。
3. PPT 真实照片与数据正确进入网页。
4. 原有计分与会话功能保持稳定。
5. 桌面、手机和减少动态效果模式均通过功能与视觉检查。
6. 用户完成本地预览验收后，再决定是否公开部署。
